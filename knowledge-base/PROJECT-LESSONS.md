
## 2026-11-27 — Policy reset must publish a complete table

Source: out/validation-2026-11-27/regression-before.log and regression-after.log.
The original packaged JARVIS module allowed 33,277 forbidden-path requests during concurrent reset/check calls. Build defaults privately and replace the table under its write lock; retain the old table on allocation failure. The fixed module completed 262,393 checks and 56,194 resets with zero forbidden allowances or ioctl errors in software-emulated QEMU. Regression counters must affect failure status, and the VM runner must require an explicit PASS marker rather than trusting QEMU exit status. This verifies the rebuilt test module, not the installed module or existing package archives.

## 2026-11-27 — Host checks require host execution

Source: out/validation-2026-11-27/hardware/ and kvm-hardware-accelerated.log.
Restricted execution hid hardware that elevated host execution could access. Host graphics, Wi-Fi, quiet audio playback, Bluetooth discovery, bounded memory/disk integrity and a fresh suspend/resume were exercised. Hardware KVM regression completed 3,079,719 checks with zero forbidden allowances. Keep device permissions intact: this account cannot open /dev/jarvis and passwordless sudo is unavailable. Distinguish an accepted asynchronous sleep/reboot request from a journal-confirmed transition.

## 2026-11-27 — Peripheral state is part of Bluetooth evidence

Source: out/validation-2026-11-27/hardware/bluetooth-pair-reconnect-audio.log.
A saved BlueZ bond does not prove current pairing or reconnection. Require the selected peripheral to advertise, prove a connected state, disconnect and reconnect it, then verify that its audio sink exists before playback. If the peripheral never advertises, report BLOCKED rather than inferring a driver failure. Restore the adapter's original power/rfkill state and record any bond removed for the fresh-pair test.

## 2026-11-27 — Separate firmware AML, user units, and kernel failures

Source: out/validation-2026-11-27/hardware/boot-issue-separation.log.
ACPI interpreter errors naming broken HP AML methods are firmware defects unless kernel evidence shows a causal driver regression. A failed per-user service with missing Hermes cron IDs is user configuration, not a failed system unit or kernel issue. Inspect definitions and registries read-only; do not rerun notification jobs during diagnosis.

## 2026-11-27 — Stability needs explicit stop thresholds and integrity proof

Source: out/validation-2026-11-27/hardware/long-stability.log.
The five-minute loaded run sampled thermals, memory, swap, root free space and new kernel messages while verifying 251,658,240 bytes through write/fsync/read/SHA-256 cycles. Define stop thresholds before load: 95 C, 512 MiB available memory, 10 GiB root free space, or any OOM, panic, Oops, MCE, I/O error, or hash mismatch. A successful process launch is not a stability pass.

## JARVIS 1.0 — Version the product separately from its Linux base

Sources: `PKGBUILD`, `out/validation-2026-11-27/RESULTS.md` and `hardware/firmware-1.0-preflight.log` under that validation directory. Use a pacman epoch when migrating from higher upstream version numbers; keep the real Linux version in `kernelrelease` for boot images and modules. Confirm package provenance, guest module-signature enforcement, and deployment separately. An autogenerated module signing key is not the publisher's package-signing key. For firmware, match a supported **board ID**, not a BIOS version number or a laptop family name.

The 1.0 gate preflight (`out/validation-2026-11-27/product-1.0.KTi79v/gate-preflight.log` and `unsigned-check.JRxnZe/guest.log` in that run directory) demonstrated two independent failures: a stale package version was rejected before boot, and a guest enforcing signatures rejected an unsigned module. Neither substitutes for loading the actual packaged module in its matching kernel.

The `clean` ext4 state alone does not establish that a VM fixture is safe to reuse: check the `needs_recovery` feature too. In `product-1.0.KTi79v/offline-base.kPSb1g/` under the validation directory, journal replay on a private reflink left two wrong allocation counts (`check.log`); only `final-check.log` records the post-repair scan. Never repair the source desktop image to prepare a kernel test.

Source: `out/validation-2026-11-27/hardware/telegram-service-removed.log`. A stale user boot unit is not a kernel failure. When its function is explicitly unwanted, disable its target link, remove the unit, reload the user manager, and verify `LoadState=not-found`; do not start the failed unit merely to diagnose it.

For a release that promises mandatory module signatures, adding `module.sig_enforce=1` only in the test command line can mask a permissive packaged configuration. Pin `CONFIG_MODULE_SIG_FORCE=y`, inspect the packaged headers configuration, and prove `sig_enforce=Y` in a guest that receives no enforcing boot argument.

## 2026-11-27 — CPU utilization alone cannot authorize process termination

Sources: `out/validation-2026-11-27/product-1.0.KTi79v/build-termination-diagnosis.log`, `monitor-cpu-policy.log`, and `/home/g0pi/JARVIS OS/kernel/self_healer.py`. A compiler, linker, package manager, or benchmark can legitimately sustain 100% CPU. The former AutoHealer killed `clang` and `ld.lld`, surfacing only as make status 143. Monitor and alert on high CPU; do not SIGTERM arbitrary processes without identity, ownership, duration, and an explicit termination policy.

## 2026-11-27 — Verify postboot policy, not only kernel defaults

Sources: `out/validation-2026-11-27/product-1.0.KTi79v/host-postboot.log`, `host-runtime-tuning.log`, and `host-postboot-final.log`. The kernel configured ADIOS and BBRv3, but later udev and sysctl files selected Kyber and BBR on the physical host. Validate the live queue and congestion-control values after reboot.
